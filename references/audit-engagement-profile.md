# Audit Engagement Profile

The engagement profile is the small set of decisions that prevents a
generic reporting method from becoming a rigid workflow. Build or load it
before collecting evidence, drafting, or reviewing. If a field is
missing, record the gap and ask; do not assume.

The fields below apply to any audit type; only the answers change. A
financial audit, an IT audit, a compliance review, a project-assurance
review, and an investigation can all use the same fields with different
answers.

## Minimum profile

| Field | What to decide | Why it matters |
| --- | --- | --- |
| Purpose | Why the engagement exists and what question it answers | Prevents evidence sprawl and report drift |
| Decisions | What the reader must decide or do | Shapes the executive layer and recommendations |
| Audience | Who reads it, at what level of detail, and in what order | Determines structure, language, and appendices |
| Scope in | Entities, processes, systems, periods, locations, populations | Defines the evidence population |
| Scope out | What is explicitly excluded, and why | Prevents overclaiming and scope creep |
| Criteria | Law, regulation, contract, policy, professional standard, or good practice | Distinguishes obligation from benchmark |
| Period and cut-off | Exact start, end, timezone, and snapshot date | Makes currency and comparability testable |
| Subject and population | The process, system, transaction set, or entity being examined | Anchors sampling and completeness |
| Evidence sources | Authoritative source, working copies, independent sources, access limits | Determines reliability and independence |
| Report type | Memo, full report, dashboard, briefing, filing, investigation report, follow-up | Selects the architecture pattern |
| Language and style | Language, tone, sentence discipline, terminology, citation style | Prevents imported style rules from another engagement |
| Materiality | Thresholds or qualitative factors that change a conclusion | Separates noise from decision-relevant issues |
| Severity scale | How impact, likelihood, and pervasiveness are combined | Prevents inconsistent ratings |
| Conclusion scale | The labels the engagement uses, e.g. satisfactory / needs improvement / unsatisfactory, or pass / conditional / fail | Prevents a borrowed scale from distorting the message |
| Approval authority | Who approves the conclusion and the release | Separates analysis from authorization |
| Gate model | Which gates exist, who owns them, and what evidence passes each gate | Avoids inventing gates the programme does not use |
| Release artefacts | Report, appendix, data pack, manifest, hashes, cover note | Defines what "issued" means |
| Confidentiality | Classification, distribution list, retention, external-sharing rules | Prevents inadvertent disclosure |

## Criteria hierarchy

Do not treat every criterion as a legal obligation. Classify each one:

1. **Legal or regulatory requirement**: mandatory; cite the effective
   instrument and the applicable period.
2. **Contractual or grant condition**: binding on the parties; cite the
   clause.
3. **Internal policy or delegated authority**: binding inside the
   organization; cite the instrument and approval level.
4. **Professional standard or framework**: authoritative guidance; say
   whether it is adopted, adapted, or used only as a benchmark.
5. **Good practice or peer comparison**: informative, not binding.

A finding that mixes categories without labeling them is easy to
challenge. State which category each criterion belongs to.

## Report-type patterns

Choose one pattern, or combine two on purpose; a short memo does not
need the full report structure.

| Report type | Typical shape | Watch for |
| --- | --- | --- |
| Board or committee memo | Conclusion, decision, few key issues, conditions, basis | Too much history; buried decision |
| Full audit report | Objective, scope, method, results, conclusion, recommendations, appendices | Repetition between executive summary and body |
| Dashboard | Indicators, thresholds, exceptions, trend, drill-down | Color-only signals; missing cut-off |
| Verbal briefing | One message, three supporting facts, one decision ask | Unsupported numbers; no record of what was said |
| Regulatory or statutory filing | Prescribed format and content | Innovating where the regulator requires a form |
| Investigation report | Chronology, evidence, findings, conclusion, actions | Mixing allegation with finding; chain-of-custody gaps |
| Follow-up report | Prior action, evidence of closure, residual risk, new issues | Accepting a management assertion as closure |

## Missing-field protocol

When a profile field is missing:

1. Record the gap in the workpaper.
2. Ask the engagement lead or approval authority.
3. If a decision cannot wait, state the assumption explicitly, mark it
   provisional, and identify what would change if the assumption is
   wrong.
4. Do not silently import a default from a different engagement.

## Adaptation points

- Which profile fields are mandatory in your methodology?
- Which report type and conclusion scale are approved?
- Which criteria categories are in use, and who confirms legal effect?
- Which gates and release artefacts does the approval authority require?
- Which language and citation profile applies?
